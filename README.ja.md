# 色そろえパズル（転置問題）の最短手数研究

English: [README.md](README.md)

サイト: <https://wand125.github.io/colorsort-transpose/>（概要、[論文](https://wand125.github.io/colorsort-transpose/paper.ja.html)、[データ](https://wand125.github.io/colorsort-transpose/data.html)、[手順の再生](https://wand125.github.io/colorsort-transpose/play.html)）。サイトの表とデータは `python3 tools/build_site.py` で `bounds.tsv` と `solutions/` から作り直す。

N 色 × N 個の玉を N+1 本のレーンで色ごとにそろえるパズルの、最短手数 T(N) についての計算結果・証明・コードをまとめたもの。
下界の証明は [LOWER_BOUND_PROOF.md](LOWER_BOUND_PROOF.md)。

## 問題

- N 色 × 各 N 個、レーン N+1 本、容量 N。
- 初期配置: レーン 0 は空、レーン 1..N はどれも下から 1,2,…,N。
- 1 手 = あるレーンの一番上の玉を、空きのある別のレーンへ移す（色の制限なし）。
- 完成: 各レーンが空か、同じ色 N 個。最短手数を T(N) とする。

N 本のスタックを空き 1 本で「転置」する問題とも言える。

- **一般の下界**: T(N) ≥ (3N²−N−4)/2。これは h（各玉は少なくとも 1 回動く）と D（2 回以上動く玉の数）の和による。
  - h+D は、N=4 の全状態で許容的（最短手数を超えない）なことを確認した。
  - 予想式との差は (N−2)(N−3)/2。
- **予想式**: (2N−1)(N−1) = n(2n+1)、ただし n = N−1。OEIS A014105（第 2 六角数）。
  - N≤7 では一致する。N≥8 では、自作の解が予想式より 8〜12 色でそれぞれ 2, 5, 9, 19, 32 手多い。
  - 8 色・12 色は Docs に既知の上界がある（106, 272）。自作ビームはどちらも下回っていない。
  - 一般の N で予想式どおりの手数を出す構成は未発見。

## 構成探しで得た事実（N=4,5 の全数探索）

- **1 ラウンド目（2N−1 手）**: 色 N の玉を、上から空レーンへ N−1 個集める。続けてレーン N の N も入れ、色 N を完成させる。レーン N の残り（N−1, …, 1）は、空いた N−1 か所へ 1 個ずつ配る。
  - この直後の局面 H_N（各レーンが [1..N−1, π(j)]）の残り最短手数は、π に依らず (2N−1)(N−2) だった。つまり 1 ラウンド目は最短解の一部になる。
- **H_N の最短解の形**: レーン [1..N−1, 1] を最後まで動かさず、最後に各色のレーンへ配っている。
  - 途中は、作りかけの色レーンの空き 1 マスへ、小さい色を一時的に退避させている。
- **G(m,k) 型の局面**: レーン j が [1..m, 余分 k 個] の形。予想値 (2N−1)(m−1) で解けるのは、余分の並びが特定の場合だけだった（`tools/gmk.py`）。
- **手で組んだ 2 ラウンド目**: N=4 では最短（21 手）だったが、N=5 では 37 手で 1 手多い。
- **`--h` モード**: 1 ラウンド目のあとレーンを凍結してビームを回すモード。N≥6 では、通常のビームより 1〜3 手悪かった（`results/h_mode_w1e6.txt`）。

## 既存研究（2026-11-14 調査）

- 匿名ページ https://piles-five.vercel.app/ が、同じ問題を「行列転置」として扱っている。
  - N≤4 は BFS、N=5 は IDA* で、値は 3, 10, 21, 36。
  - (2N−1)(N−1) は、これらの値に 2 次式を当てはめた予想で、構成も下界の証明もない。N=6, 7 は予想のまま。
- Ito ほか「Sorting Balls and Water」FUN 2022（arXiv:2202.09495）
  - 同色の上か空レーンにしか置けない版で、解けるかどうかの判定が NP 完全。
- Althaus ほか「Sorting Colored Balls in Colored Tubes」SoCS 2025
  - 別ルールの版で、最小手数を求めるのが NP 困難。
- Szegedy・Yu「On Rearrangement of Items Stored in Stacks」（arXiv:2002.04979、のち「Rubik Tables and Object Rearrangement」、IJRR 2022）
  - n 本×高さ d・空き 1 本の一般の並べ替えを O(nd) 手で解く（d = n を含む）。下界は数え上げの Ω(nd) だけ。
  - 本問題では T(N) = Θ(N²) が言える。明示された定数は 7nd(1+log d)（n ≥ d の再帰版）と 27nd（d ≤ √n）だけで、係数の下界や小さい N の値は載っていない。
  - よって残る問いは係数 c = lim T(N)/N²。いまの下界は 1.5、予想式（目安）は 2、組み立ての上界は約 4.2（24 色）。
- Han・Stiffler・Bekris・Yu「Efficient, High-Quality Stack Rearrangement」（arXiv:1706.09949、RA-L 2018）
  - w+1 本・深さ d・満杯で空き 1 本という、本問題と同じ形の設定を扱う。
  - 下界は数え上げのオーダー（Ω(wd)、Ω(wd·log d/log w) など）だけで、定数つきの下界や「2 回動く玉」の議論は無い。
  - 小さい場合の最適値は、ランダムな初期配置 100 個の平均（w=2〜4、d=3 など）だけで、転置の配置や満杯の 5×5 は無い。
- この初期配置の T(N) について、一般の下界・7 色の手順・8 色以上の値を載せた文献は見つからなかった。
- 港のコンテナ積み替えを扱うブロック再配置問題の文献は未調査。

### beam の使い方

```
colorsort N WIDTH [--lambda X] [--mu Y] [--r1] [--r2] [--h] [--fin Z] [--window W] [--noise K] [--seed S]
```

- `--r1`: レーン N を凍結し、最後に配る。
- `--r2`: 色 k は、空レーンか色 j ≥ k の上にだけ置ける。
- `--h`: 1 ラウンド目のあと、レーン [1..N−1,1] を凍結する。
- `--mu`: D の重み。
- `--fin`: 完成に近いレーンへの加点。効果はなかった。
- `--window`: 直近 W 層に出た状態へ戻らないようにする。既定は 6。7 色 78 手はこの設定で見つかった。

### lowerbound の使い方

```
colorlb init N          # 初期局面の h, D と一般式
colorlb check N         # h+D が許容的か全状態で確かめる（N≤4）
colorlb prove N B       # g+h+D ≤ B−1 だけたどって完成に届かなければ T ≥ B（N≤6）
colorlb opt N L0 L1 …   # 任意局面から A*。レーンは下から 16 進、空は "."
```

ビルドは `nice -n 15 cargo build --release --offline -j 2`。
下界 J を使う証明探索は `COLORLB_JOINT=1 colorlb prove N B`。6 色の B=55 は 471 万状態で終わる。

## 次の候補

1. 7 色の確定（いまは 75 ≤ T(7) ≤ 78）。証明する手数を 1 上げるごとに状態数が 7〜10 倍になるので、下界 J をさらに強くする必要がある。
2. 一般の N の下界の係数を 1.5 から上げる。J が数えていないのは、同じ玉が 2 回以上「一時置き」される分。
3. 8 色以上の上界を下げる（ビームの評価に J を使う、組み立ての改良）。
