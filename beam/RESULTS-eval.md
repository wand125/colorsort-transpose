# 注ぎ単位ビームの評価比較

## 主な結果

小幅1000で8設定×3色×5種（120試行）を比較し、上位3設定を幅3000×同じ5種（45試行）で確認した。確認幅の3色の正規化中央値の平均で最良は **random7**、既定比 **4.12%改善**。

- 13色・幅3000: 中央値350手（既定346手、差+4手）。
- 15色・幅3000: 中央値494手（既定532手、差-38手）。
- 17色・幅3000: 中央値689手（既定736手、差-47手）。

小幅と確認幅の集約順位のSpearman相関は **0.50**。相関は選択した3設定に限る記述統計で、幅10万以上の性能は未測定。

全165試行のうち129件で解を得て、全手順を独立replayで再確認した。未完走を明記し、分布表・失敗内訳に掲載した。

仕様に記載された13・15・17色の記録更新はなかった。12色の参考ケースは既定・幅2000・種6で272手に到達。

`SPEC-eval.md` に従い、評価4項と乱数幅のCLI、複数種の比較・学習・選抜ツールを実装した。生出力、全コマンド、バイナリとソースのSHA-256、各手順のreplay結果は [eval-runs/](eval-runs/) に保存。

## 追加した評価

`f = M + aT + bS + dP + w_depth·B + w_empty·E + w_near·Q + w_pairs·R`。小さい方を優先する。既存4項は完成局面で0、新しい項は完成局面にも加算する（完成時E=1）。

既存項は、M=各色について底の同色連続の最大長だけを残したときの残り玉数、T=レーン内の隣接色の変化数、S=各色が現れるレーン数−1の総和、P=底から1,2,3,…と並ぶ連続部分の長さの総和から大きい2本を引いた値。

- `--w-depth`: Bは各玉の上の異色玉数の総和。同じレーン内の異色の玉対を1回ずつ数える。
- `--w-empty`: Eは空レーン数。N²玉・容量NのN+1レーンなので、この問題ではEは0か1。
- `--w-near`: Qは底の同色連続より上に異色を含む玉が1〜2個だけあるレーン数。完全単色は含まない。
- `--w-pairs`: Rは移動元≠移動先、双方非空、最上色が一致、移動先に空きがある順序付きレーン対の数。上の塊全部が入ることまでは要求しない。
- `--w-t/--w-s/--w-p` は既存の `--a/--b/--d` の別名。`--noise` は `[0,noise)` の決定的乱数幅。既定0.02。

新4項の既定重みは0。全0なら追加の特徴計算を行わず、元の浮動小数点演算順序と出力形式を維持する。B/E/Qは2レーン差分、Rは最上色ごとの移動元数・移動先数の差分から計算する。h+D加算は今回は未採用（既存実装の全候補計算は高価なため）。

初期計測では終局で新項も一律0に戻していたため、空レーン項の終局値を含む線形和に修正し再計測した。初期版の出力は `eval-runs/preliminary-goal-zero/` に隔離し、以下の比較・選抜には一切含めていない。

## 環境・計測方法

リポジトリ根で実行。macOS 26.2 / arm64 / 論理14CPU / 48GiB、rustc 1.99.0、rayon 1.12.0。開始時load averageは157.76/150.16/149.28。正式計測は `nice -n 10`、1本4スレッド、同時最大2本。15秒間隔の優先度・実行数の観測は `eval-runs/priority-samples.jsonl`。既存の他の計算は停止・変更していない。

予算は小幅1000で8設定×3色×5種、確認幅3000で小幅の上位3設定と既定。種は両幅とも1〜5。小幅の選抜スコアは各色の `設定の中央値 / 既定の中央値` の3色平均で、低い方を採る。同点は設定名順。5本すべて検証成功した設定だけを選抜する。標準偏差は母標準偏差（分母K）。失敗を除いた統計は参考値で、完走不足の設定は比較順位に入れない。

幅3000の17色の予備計測に約320秒かかったため、指定の例（幅3000〜10000）より小さな1000から探索した。確認幅はその3倍。幅10万以上は実行していない。予備計測は初期のnice適用失敗後に自分のプロセスだけNI=10へ補正したため、正式比較の時間から除外。ビルド・正式比較は権限制約外の承認済み実行でniceを適用した。

実行時間は高負荷の影響を受ける。各JSONに壁時計、timeのCPU秒・最大RSSを保存するが、選抜には手数だけを使う。全探索は既定のmax-g=3N²、上界枝刈りなし。

```sh
nice -n 10 env CARGO_TARGET_DIR=beam/target-pour CARGO_BUILD_JOBS=4 cargo build --release --offline --manifest-path beam/Cargo.toml --bin pour
nice -n 10 env CARGO_TARGET_DIR=beam/target-pour CARGO_BUILD_JOBS=4 cargo test --release --offline --manifest-path beam/Cargo.toml --bin pour -- --test-threads=1
/usr/bin/python3 -B tools/pour_tune.py 13 15 17 --configs beam/eval-runs/configs.json --training beam/eval-runs/training-best.tsv --trials 8 --width 1000 --confirm-width 3000 --top 3 --seeds 1 2 3 4 5 --threads 4 --jobs 2 --timeout 1800 --out beam/eval-runs/tune
```

Python親プロセスは通常優先度で起動し、探索子プロセスにniceを一度適用する。実行許可上niceが使えない場合はstderrの警告を検出して成功計測に含めない。タイムアウト時に終了するのは当該ツールが新規作成した専用プロセスグループのみ。再開時はコマンド・重み・バイナリ/ソースハッシュ・種・制限時間を照合し、手順を再replayしてから再利用する。

## 学習した重み

作業開始時の `solutions/best.tsv`（保存コピー: [training-best.tsv](eval-runs/training-best.tsv)）の12〜20色、計5350局面（単一玉の各移動前と終局）をreplayして採取。入力TSVのSHA-256は `631709eaafa8249699d9e91ab97331ed5adc0ac09b8211a4e86ad5a18fb1457e`。N=12の学習手順は当該TSV記載の285手で、仕様が挙げる272手とは別。目的変数はその既知手順に沿った残り手数で、最短距離ではない。
